# Лабораторная работа № 5: проверка реализации

Основные модели данных содержатся в `app/models.py`; ER-диаграммы приведены в `docs/DATA_MODEL.md`.
Алгоритмы функций Ф1-Ф7 и их UML-состояния описаны в `docs/ALGORITHMS.md`.
Структура модулей приведена в `docs/ARCHITECTURE.md`.

## Функциональные границы

- Ф1: приём JSON и CSV, проверка Pydantic, предотвращение повторов по паре источник/внешний ID.
- Ф2: интенсивность в транспортных средствах в час, прогноз на 5, 10 и 15 минут; выбор между средним последних пяти минут и последним наблюдением по MAE при наличии контрольных пар.
- Ф3: сравнение только утверждённых программ при наличии загруженных оценок транспортной модели.
- Ф4: создание решения и подтверждение с проверкой имени автора (без аутентификации); возвращается пакет для работы через АСУДД, а не команда контроллеру.
- Ф5: карточка события и изменение его статуса.
- Ф6: отчёты и сопоставление периодов при сопоставимой загрузке и условиях; изменение интенсивности не приравнивается к измеренной задержке.
- Ф7: регистрация обращения и привязка к светофорному объекту без хранения контактов заявителя.

## Воспроизведение

Установить зависимости из `requirements.txt`, подготовить переменные среды по `.env.example`,
развернуть PostgreSQL с помощью `docker-compose.yml`, выполнить подготовку справочников
согласно `docs/SETUP.md`. Запуск тестов: `python -m pytest -q`.

Отдельные граничные проверки математических функций содержатся в
`tests/test_lab5_additional.py`. При финальной проверке 25.11.2026 выполнена команда `python -m pytest -q tests/test_api.py tests/test_logic.py tests/test_lab5_additional.py` на локальной SQLite: `13 passed, 2 warnings`. Совпадение исходных файлов и тестов с репозиторием подтверждено по Git-хешам. Два предупреждения связаны с устаревающим обработчиком `on_event` FastAPI. Генерация DDL для девяти ORM-таблиц отдельно проверена через диалект PostgreSQL. Запуск PostgreSQL и результат GitHub Actions в рамках этой проверки не подтверждены.
